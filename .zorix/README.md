# Рабочее пространство AI в проекте Zorix

Статус документа: черновик.

Каталог `.zorix/` предназначен для работы AI-ассистентов и участников проекта с контекстом Zorix. Это не часть пользовательской документации, не описание готовой реализации и не runtime-конфигурация платформы.

Задача этого пространства — помочь сохранять единое понимание проекта при работе с документацией, архитектурными решениями, обзорами изменений и подготовкой будущих релизов.

## Назначение

`.zorix/` фиксирует рабочий контекст, который должен учитываться при взаимодействии AI с репозиторием:

- что такое Zorix на текущем этапе;
- какие границы проекта уже определены;
- какие принципы нельзя нарушать при подготовке документов;
- как проверять изменения перед review;
- как подходить к релизной подготовке, когда она появится;
- какие правила использовать при работе Codex с проектом.

Этот каталог помогает снизить риск того, что AI начнет додумывать функции, писать преждевременный код или менять смысл проекта без явного решения maintainers.

## Содержимое

`context/` содержит базовый проектный контекст для AI и участников проекта.

`checklists/` содержит проверочные списки для review и релизной подготовки.

`prompts/codex/` содержит инструкции и рекомендации для работы Codex с репозиторием.

## Основные правила работы

На текущем этапе Zorix находится в фазе формирования основания проекта. Поэтому при работе с репозиторием важно:

- писать документы на русском языке;
- не добавлять маркетинговые формулировки;
- не обещать функциональность, которой еще нет;
- не создавать код без отдельного явного решения;
- отделять видение проекта от технической реализации;
- фиксировать ограничения так же внимательно, как и цели;
- уважать существующие файлы и не менять их без необходимости.

## Как использовать этот каталог

Перед подготовкой изменений AI-ассистент должен прочитать релевантные документы из `context/`.

Перед отправкой результата на review следует свериться с `checklists/review.md`.

Перед подготовкой релиза или релизных заметок следует свериться с `checklists/release.md`.

При работе через Codex следует учитывать инструкции из `prompts/codex/README.md`.

## Граница ответственности

Документы в `.zorix/` помогают направлять работу, но не заменяют решения maintainers.

Если между документами есть противоречие, приоритет должен быть у явно сформулированного запроса maintainers и актуальных проектных документов в репозитории. Спорные изменения лучше выносить на обсуждение, а не маскировать как техническую правку.
