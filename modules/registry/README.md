# Registry

`modules/registry` содержит центральный компонент, управляющий жизненным циклом зарегистрированных адаптеров.

Registry работает только через контракт `Adapter` из `core_model`. Он не импортирует конкретные адаптеры и не знает заранее типы ресурсов, которые эти адаптеры возвращают.

## Роль Registry

Registry отвечает за:

- регистрацию экземпляров адаптеров;
- запрет повторной регистрации адаптера того же класса;
- хранение текущего набора зарегистрированных адаптеров;
- запуск `discover()` у всех зарегистрированных адаптеров;
- объединение найденных ресурсов в единый список;
- очистку списка зарегистрированных адаптеров.

Registry не выполняет поиск адаптеров на диске и не импортирует Python-пакеты. Этим занимается `PluginLoader`.

## Жизненный цикл адаптеров

1. Внешний код получает экземпляры адаптеров.
2. Экземпляры передаются в `Registry.register()` или `Registry.register_many()`.
3. Registry проверяет весь входной набор и сохраняет адаптеры по типу класса.
4. При вызове `scan()` Registry вызывает `discover()` у каждого адаптера.
5. Результаты всех адаптеров объединяются в один список ресурсов.
6. При вызове `clear()` Registry удаляет все зарегистрированные адаптеры.

Повторная регистрация адаптера того же класса запрещена. Это защищает Registry от дублирования результатов при последующем `scan()`.

`register_many()` работает атомарно. Если в переданном наборе есть дубликат класса адаптера или конфликт с уже зарегистрированным адаптером, Registry выбрасывает `DuplicateAdapterError` и не регистрирует ни один адаптер из этого набора.

`adapters()` возвращает `tuple` зарегистрированных адаптеров в порядке регистрации. Возвращаемое значение нельзя использовать для изменения внутреннего состояния Registry.

## Поведение scan()

`scan()` вызывает `discover()` у зарегистрированных адаптеров последовательно.

Registry не подавляет и не оборачивает исключения из `discover()`. Если адаптер выбрасывает исключение, оно передается вызывающему коду. Это текущее fail-fast поведение.

## Схема взаимодействия Registry и PluginLoader

`PluginLoader` отвечает за загрузку адаптеров:

1. находит пакет адаптера;
2. импортирует его;
3. проверяет наследование от `Adapter`;
4. создает экземпляр адаптера;
5. возвращает список адаптеров.

`Registry` принимает результат работы `PluginLoader`:

1. получает список адаптеров;
2. регистрирует их через `register_many()`;
3. запускает `scan()`;
4. возвращает единый список ресурсов.

Такое разделение сохраняет простую границу ответственности: `PluginLoader` занимается загрузкой, а `Registry` управляет зарегистрированными адаптерами и сбором ресурсов.
