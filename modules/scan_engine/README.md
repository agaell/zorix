# Scan Engine

`modules/scan_engine` содержит прикладной компонент, который запускает обнаружение ресурсов через `Registry` и возвращает структурированный результат сканирования.

Scan Engine не загружает плагины, не регистрирует адаптеры и не знает конкретные реализации адаптеров. Он работает с уже подготовленным `Registry`.

## Роль Scan Engine

`ScanEngine` отвечает за:

- последовательный вызов `discover()` у зарегистрированных адаптеров;
- сохранение найденных ресурсов в порядке регистрации адаптеров;
- формирование `ScanResult`;
- фиксацию ошибок адаптеров в режиме `continue_on_error`.

## Отличие от Registry

`Registry` управляет зарегистрированными адаптерами: добавляет, хранит, возвращает и очищает их.

`ScanEngine` использует `Registry` как источник адаптеров и отвечает за прикладное поведение сканирования: статус, ошибки и структуру результата.

## Режимы сканирования

По умолчанию используется fail-fast режим.

Если `discover()` выбрасывает исключение, `ScanEngine` не подавляет и не оборачивает его. Сканирование останавливается, а исходное исключение передается вызывающему коду.

Если вызвать `scan(continue_on_error=True)`, `ScanEngine` сохранит ошибку в `AdapterScanError` и продолжит сканирование остальных адаптеров.

Итоговый статус:

- `SUCCESS` — ошибок нет;
- `PARTIAL` — есть ошибки и есть успешно найденные ресурсы;
- `FAILED` — есть ошибки и нет успешно найденных ресурсов.

## Структура ScanResult

`ScanResult` содержит:

- `status` — итоговый статус сканирования;
- `resources` — tuple найденных ресурсов;
- `errors` — tuple ошибок адаптеров.

Дополнительные свойства:

- `succeeded`;
- `failed`;
- `partial`.

`ScanResult` и `AdapterScanError` являются неизменяемыми dataclass.

## Пример использования

```python
registry = Registry()
registry.register_many(adapters)

result = ScanEngine(registry).scan(continue_on_error=True)
```
